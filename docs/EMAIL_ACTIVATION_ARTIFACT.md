# Offline registration email artifact

`tools/email/build-activation.mjs` prepares a separate immutable **PREPARATION_ONLY**, Functions-only package from an explicit clean Git HEAD on a dedicated branch. It leaves the frozen 70-target restart builder, manifest and deployment guard unchanged. Its exact entry exports are `createEventRegistration`, `updateEventRegistration`, `cancelEventRegistration`, `dispatchRegistrationEmail` and `deliverEmailTask`.

Use an installed Node 22 process, an explicit full 40-character SHA equal to current HEAD, and a **new** destination below ignored `.local-data`. No SDK, bucket, mailbox selection, OAuth input, secret value or runtime configuration input is accepted. The tool does not install dependencies, execute Functions handlers, discover endpoints, access the cloud, provision resources, deploy or send messages.

```text
node tools/email/build-activation.mjs --source-sha CURRENT_FULL_40_HEX_HEAD --out .local-data/email-artifacts/NEW_UNIQUE_DIRECTORY
node --test tools/email/build-activation.test.mjs
```

Preparation compiles quiz-domain and Functions into a separate fresh sibling `.work` directory, with source maps disabled and an isolated compiler environment. The compiler receives only OS bootstrap variables and its own temporary/home directories; ambient credentials, Node preloads, project/runtime settings and `.env` values are absent. On Windows, libuv can fill missing bootstrap variables from the parent even when spawning with an explicit environment. The builder therefore explicitly sets `PATH` to its own temporary directory without executables, derives `HOMEDRIVE`, `HOMEPATH` and `SYSTEMDRIVE` from that directory, and sets `USERNAME`, `USERDOMAIN` and `LOGONSERVER` to synthetic values. The parent's PATH and user values are not inherited; POSIX children have no PATH. The existing pnpm TypeScript junction is explicitly resolved to physical repository-local dependencies and its installed version checked against the lock. Missing dependencies cause failure; there is no automatic install. All source and output paths reject symlinks/junctions, except that explicitly resolved compiler dependency junction.

The targeted entry follows relative compiled JavaScript imports and accepts only inventoried runtime packages and Node builtins. Dev helpers, health, organizational email callables, path escapes, source maps and unrelated artifact files are refused. Shared registration, authorization, delivery and team-message formatting helpers may belong to the closure because current modules import them; that does not export organizational email endpoints or activate organizational intents. The vendored quiz-domain is compiled from the same source. Runtime package declarations and the exact package lock reuse the unchanged restart packaging contract; package scripts are removed. The artifact contains no installed `node_modules`, Hosting, Security Rules, Storage files or deployment commands/configuration.

`receipt.json` records source SHA, branch, Node/compiler versions, exact five targets, file SHA-256 hashes, aggregate tracked-input hash, frozen-manifest hash, required activation parameter **names** and secret **names**. It explicitly records `deploymentApproved: false`, `runtimeDiscoveryVerified: false`, `dependenciesInstalled: false`, and unverified cloud inventory. Receipt integrity is returned as a hash in stdout; receipt hashes cover package payloads, excluding the receipt itself. The builder rechecks clean HEAD and tracked input hashes before and after completion. Any failure preserves partial local output without a successful stdout receipt; use a new destination after investigating. It never resets or overwrites a destination.

This phase proves compilation and static package scope only. Default email mode is `off`: worker handlers remain disabled and email secret bindings remain absent until separately reviewed scoped staging configuration is supplied. A package by itself is **not ready for activation**. A lead-reviewed, controlled, network-blocked compiled SDK discovery must still confirm the exact five exported endpoints, endpoint options, private worker invocation and off/staging parameter/secret bindings. Offline discovery must not invoke handlers or resolve actual secret/provider values. Fresh cloud inventory, exact identities/queue/IAM, real secret versions, human Gmail `gmail.send` consent, approved runtime cutoff/recipient/origin/sender and a bounded approved send remain separate gates. See [EMAIL_ACTIVATION_PLAN.md](EMAIL_ACTIVATION_PLAN.md) for scope and containment.

Synthetic tests exercise entry selection, dependency closure, environment isolation, input drift, destination/path guards and exact artifact scope without compiling or importing the application. One actual Node child with no imports proves an exact closed environment despite synthetic parent credential, preload, PATH and user values; it reports only booleans. Their generated fixture and small check log stay under ignored `.local-data/email-artifact-tests`. A synthetic PASS does not establish Firebase SDK discovery, cloud configuration or Gmail delivery.
