## Přesný cleanup a audit

Tento oddíl je budoucí možnost vyžadující samostatný souhlas. V doporučeném retenčním běhu se cleanup neprovádí; po skončení vlastní session se pouze zaznamenají všechny ponechané IDs a jejich stav.

Po akceptaci/selhání zastavit QA contexts; skončit vlastní live session. S approved event cleanup aktérem trash → konkrétní delete plan → confirm `deleteEvent`; uchovat plan hash, expected revision, retained snapshot IDs a deletion/tombstone/audit receipts. Nesmazat sdílený snapshot jen kvůli názvu QA.

Separátní schválený operator cleanup musí před **první** destruktivní akcí ověřit všechna owned roots a vazby: quiz/event `createdBy===operatorUID`, přesný namespace, snapshot/session `eventId`, public counterparts, asset `quizId/createdBy/generation`, obě Auth/membership UID a `.test` identity. Poté s preconditions odstranit jen zachycené vlastní Library quiz descendants/roots, příslušné Storage generations a dvě Auth/memberships. Žádný broad prefix delete, claim reset, jiné accounts, accessControl reset nebo automatické unpause. Při rozporu STOP, zachovat všechny remaining IDs; nevymazat důkazy po částečném selhání. Globální audit, tombstones a předepsané operation logs ponechat podle aktuálního retention kontraktu.

Receipt: přesný source/tree, deploy/runtime/Hosting IDs (až budou skutečně ověřené), projekt/bucket; schválení každého write rozsahu; UTC kroky, Auth UID bez hesel, safe grants/version/scope, accessControl revision/updateTime, všechny dynamické QA IDs a parent vazby, requestId/revisions/error codes, asset paths/generations/hash, source/snapshot/final fingerprints, obrazovky bez credential fragmentů, cleanup plan/remaining IDs a výsledky každého CAS/generation delete. Tokeny, passwords, session cookies a ID tokens odděleně chránit a po schváleném cleanup zneplatnit; report je neobsahuje.

Výsledek **PASS** jen pro skutečně provedené položky a kompletní schválený cleanup/retention. Při neuzavřeném provisioningu je výsledek **BLOCKED BEFORE WRITES**, ne online PASS. Žádný merge/deploy, skutečné emaily nebo fyzická provozní připravenost z tohoto návrhu nevyplývá.
